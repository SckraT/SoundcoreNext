# 01 — Core A3954 state and commands

**Status:** done
**Blocked by:** —

## Goal

Add A3954 parsing and write bodies to `core/crates/models` and
`core/crates/session`, without changing A3062/A3949 behavior.

## Requirements

1. Add `DeviceState.a3954: Option<A3954State>` or equivalent; every existing
   `DeviceState` constructor gets the field (`None` except A3954).
2. Parse the 165-byte A3954 `01 01` body from the reference parser:
   - base TWS fields 0..32 share the existing parser;
   - case firmware 32..37, case battery 37, case serial 38..44;
   - equalizer preset id 44..46, left/right 10 bands 46..56/56..66;
   - HearID block kept raw for writes;
   - buttons 116..124, ambient cycle 124, sound modes 125..129,
     case features 132..136, air pressure 136, low battery 140, LDAC 141,
     dual 142, auto power off 143..145, limit 145..148, spatial 148..151,
     easy chat 151..152/158, leak 153, case language 157, wearing 159,
     slide buttons 161..165.
   Validate the exact offsets against the reference on the committed capture.
3. A3954 sound-mode scale state and command builder (`06 81` 5-byte body).
4. A3954 equalizer: 22-preset catalog (common_settings_type_2), visible 8 bands,
   114-byte preset/custom body preserving HearID, model-aware API.
5. A3954 non-button setting commands: LDAC `01 FF`, dual `0B 84`/`0B 01`/writes,
   auto-off `01 86`, limit volume `20 82`/`20 81`, low battery `10 82`,
   cycle `06 82`, wearing `01 81`, leak `10 9A`, spatial `10 81`,
   easy chat `10 9D`, case language `07 8A` (if included).
6. Session methods for scale, A3954 EQ and A3954 setting writes; clear
   unsupported errors for others.
7. Tests: parse the committed real capture; every command body vector; A3062
   regression; no serial in debug/log output.

## Implementation (2026-11-23)

### State (real 165-byte `01 01` body)

`DeviceState.a3954: Option<A3954State>` is additive: every other model keeps
`None`. The base TWS fields 0..32 are the existing `parse_tws_cmm2_body`; the
A3954 block is parsed from the measured offsets below, and a body shorter than
165 bytes is `ShortBody { minimum: 165 }` instead of being parsed with invented
offsets.

| body | field | measured value in the committed capture |
|---:|---|---|
| 0 | host device | `1` Right |
| 1 | TWS connected | `1` |
| 2, 3 | left/right battery (100 scale) | 96, 98 |
| 4, 5 | left/right charging | 0, 0 |
| 6..11, 11..16 | left/right firmware | `04.29`, `04.29` |
| 16..32 | earbud serial, kept internal | masked to ASCII zeroes in the fixture |
| 32..37 | case firmware | `01.58` |
| 37 | case battery, raw `0..9` + 1 of 10 (255 = unavailable) | 9 |
| 38..44 | case serial, `3954` + six hex bytes, internal | zeroed in the fixture |
| 44..46 | equalizer preset id, LE | `FE FE` custom |
| 46..56 | left channel, ten bands `byte - 120`; leading `FF` = absent | `[18, 8, 0…]` |
| 56..66 | right channel, ten bands | absent (`FF × 10`) |
| 66 | unknown (app: age range) | 0 |
| 67..115 | HearID block, 48 raw bytes kept for writes | zeros |
| 115 | unknown | `0A` |
| 116..124 | eight main-button bytes (remapping deferred) | `66 66 32 33 FF FF 44 44` |

Closed enums are validated (unknown sound mode/slider/airplane/auto-off
index/dB limit/refresh/music mode/spatial mode/wait time/language are typed
`StateError`s); flags only read as on when the byte is exactly `1`.

### Sound-mode scale

`A3954SoundModeSlider` is a validated 1..=11 position: 1..=5 transparency
(1 strongest), 6 normal, 7..=11 noise canceling (11 strongest). The measured
`06 81` body is `[mode, position, airplane, wind, 0xFF]`
(`A3954SoundMode::command_body`); all eleven app writes in the capture match:
normal at 6, transparency at 1..5, noise canceling at 7..11, with wind `01`.
The state's wind detection bit is read-only and is not written.

### Equalizer

- 22 presets from OpenSCL4's `common_settings_type_2` table (the A3954 table),
  ids 0..21, including Bass Booster at id 2 and no `0x7E7E`; exposed as
  `A3954_EQUALIZER_PRESETS` / `a3954_equalizer_preset` /
  `DeviceModel::a3954_equalizer_presets`.
- 8 visible bands, 10 bands per channel, invisible custom bands fixed at
  `[0, 0]` raw (`A3954_FIXED_EQ_BANDS`).
- `DeviceModel::a3954_equalizer_preset_body` and
  `DeviceModel::a3954_custom_equalizer_body` build the measured 114-byte
  `03 87` body: preset id LE, favorite music genre, both channel curves,
  unknown `FF FF` (the app's measured bytes; OpenSCL4 sends `00 00` and that
  variant was never sent), cleared HearID enabled flag, HearID left/right
  volume adjustments/time/type/custom adjustments copied verbatim, the active
  curve interleaved with zeroes for both channels and two trailing zeroes.
  The built bodies equal the two app-captured bodies byte for byte (Rock id 17
  and Signature id 0).

### Setting commands

`A3954SettingCommand` with exact measured bodies:
`01 FF` LDAC, `0B 84` dual connections, `01 86` auto power off (10/20/30/60),
`20 82` limit high volume, `20 81` refresh, `10 82` low-battery prompt,
`06 82` ambient cycle, `01 81` wearing detection, `10 9A` sound-leak
compensation, `10 81` spatial audio `[enabled, music_mode, mode]`, `10 9D`
easy chat `[enabled, wait_time]`, `07 8A` case language. The `0B 01` list and
`0B 82`/`0B 81`/`0B 83` connect/disconnect/forget reuse the existing
dual-connections helpers (the A3954 model now enables them).

### Session

`set_a3954_sound_mode`, `set_a3954_equalizer_preset`,
`set_a3954_custom_equalizer` and `set_a3954_setting` write exactly one frame
and never read; the empty ack frames and notifications are skipped by the next
`poll_state`. A model without the A3954 blocks writes nothing and returns the
existing `UnsupportedSoundMode` / `UnsupportedEqualizer` / `UnsupportedSetting`
errors (no new session error variants, so the desktop matches stay unchanged).

### Fixtures

`core/data/a3954-state.json` (real capture, earbud serial masked to ASCII
zeroes, case serial zeroed, no address, checksum recalculated),
`core/data/a3954-sound-modes.json` (the eleven real `06 81` writes) and
`core/data/a3954-eq-presets.json` (the two real app 114-byte `03 87` bodies).

### Desktop

No behavior or UI change: three existing `DeviceState` literals in the desktop
tests gained the new `a3954: None` field so the crate keeps compiling
(`desktop/src/overview.rs`, `desktop/src/controller.rs`). The A3954 pages are
tickets 02/03.

### Deferred (deliberately, documented in code)

Button remapping (the eight main and four slide bytes are parsed raw), the
`07 87` case-features write, air-pressure writes, HearID editing, the case
display's brightness/color/style/connection fields, the `07 88` case display
read and changing the airplane-mode update setting on its own (the byte is
parsed and the `06 81` body carries it, but no UI action writes it).
